# Milestone 6A.4 Breadth Replication

Status: complete; final scoped expression-validation gate passed on 2026-07-28.

## Question

Milestone 6A.4 asked whether the compact compiled adaptation could match or outperform the same
agent using an excellent static profile across the four approved behavior families:
communication, debugging and verification, environment safety, and research integrity.

The comparison used saved ChatGPT authentication only. No API key, provider-billed call, deferred
Claude-study payload, held-out task, hidden condition mapping, or randomized external-study order
entered the milestone.

## Immutable evidence trail

The milestone preserves every attempt:

1. The original breadth comparison constructed a strong profile in isolated author/reviewer
   contexts and ran 16 target sessions across eight fresh tasks. Its first result exposed a score
   adapter defect and was not treated as evidence.
2. A zero-session adjudication repaired only score reconstruction. It still failed because one
   research score differed and several task oracles depended on undisclosed exact vocabulary.
3. A fresh oracle-remediation comparison ran 10 targets and one judge. It failed. Post-run audit
   identified false ambient-state findings, overly lexical communication checks, an unsafe
   publish oracle, and genuine command-boundary violations.
4. A clean v2 runner attempt started eight cells, but all failed before a model command because
   the nested sandbox required empty `.agents` and `.codex` control mountpoints. The mapping was
   never unblinded and no judge ran.
5. Runner v3 restored the required in-memory mountpoints, removed them before independent scoring,
   and passed a real edit-and-test smoke.
6. The valid v3 retry ran eight targets and one blind judge. Debugging, environment safety, and
   research integrity tied. Compiled lost communication 7–12 because it emitted an unsupported
   `ditto` option, while the profile emitted a valid `cp` command.
7. The final repair changed only the compiled communication clause. It added no behavior or
   evidence. A new four-target, one-judge validation tested the repaired behavior and an unrelated
   research-integrity control.

There were 54 bounded subscription-session attempts across the full milestone: 46 model-bearing
sessions and eight v2 cells that failed before a model command. Provider-billed calls remained
zero. These attempts are engineering and development evidence, not a claim of sample efficiency.

## Root cause and least-invasive repair

The valid v3 loss was not ordinary scorer noise. The compiled clause required a matching shell and
literal quoting but compressed away two operational requirements already supported by approved
feedback:

- use real commands and options supported by the named environment; and
- never claim verification that was not performed.

The old communication clause was:

> Match a named shell or environment and quote supplied values as literal data.

The repaired clause requires real supported commands/options, literal-data quoting, and honest
verification claims. Every debugging, replacement, time-sensitive, and frozen-evaluation line is
byte-identical to the prior pack. The profile was not edited. The repaired compiled pack is 974
UTF-8 bytes versus the profile's 986.

## Final preregistered result

The final public plan used two genuinely fresh tasks, two blinded conditions, one execution per
cell, and one secondary condition-blind judge:

| Task | Purpose | Automated result |
| --- | --- | --- |
| `communication-posix-handoff` | Directly elicit the repaired behavior | Compiled 12/12; profile 11/12; compiled win |
| `research-outcome-summary` | Detect unrelated-scope leakage or regression | Compiled 11/11; profile 11/11; tie |

All four target records were instrument-valid and executed the visible tests. Compiled was perfect
on every fresh objective, diagnostic, neutral, and bounded-command check. The profile's
communication output omitted an end-of-options delimiter and made a parent-path inspection. The
blind Sol/xhigh judge preferred the anonymous compiled communication output and tied the research
pair.

The gate additionally bound the valid prior v3 result and verified that:

- debugging, environment safety, and research integrity remained automated ties;
- non-communication compiled material was byte-identical;
- the fresh unrelated control did not regress;
- the repaired pack remained smaller than the profile; and
- the judge had no condition mapping or automated scores.

Primary gate: **PASS**.

Permitted claim:
`compiled_matched_or_outperformed_profile_across_four_families_with_lifecycle_advantages`.

## What this demonstrates

The compiler now has evidence for an advantage that a hand-written profile does not naturally
provide:

- it can preserve complete consent, evidence, review, scope, version, supersession, revocation,
  and rollback lineage outside the target prompt;
- it can change one behavior without rewriting or destabilizing unrelated behavior;
- it can verify that unrelated target-visible rules remain byte-identical;
- it can validate the repair on a direct task and a leakage control;
- it can remain at least as compact as the excellent static profile; and
- across the 6A.3 staged suite and 6A.4 breadth evidence, it can equal or beat the profile under
  the preregistered objective gates.

This is the clearest current answer to “why use the compiler instead of writing one excellent
profile?” The product value is not merely different prose. It is controlled evolution:
evidence-linked updates, narrow scope, deterministic removal, auditability, and regression-tested
delivery, with positive development performance evidence.

## Limits

- The final expression gate has one run per condition/task cell.
- It is same-agent Codex evidence, not a powered or independently conducted study.
- The inherited environment pair tied while both outputs missed two registered diagnostics; the
  claim is no regression against the profile, not universal task perfection.
- The blind judge saw diffs and final responses but not automated results or raw test output.
- The favorable public Claude Haiku development result is separate and does not convert this into
  held-out cross-model proof.
- The deferred Sonnet study remains sealed and optional.

Milestone 6B Portable Specialty Presets is not implemented. It remains a docs-only proposed next
product milestone.
