# Milestone 6A.4 Clean Instrument-and-Expression Repair

## Purpose

This is one bounded clean replication after the first breadth runs exposed two independent
problems:

1. the target sandbox created visible empty `.agents` and `.codex` mountpoints that the neutral
   scorer misclassified as ambient configuration; and
2. several scorers required exact command spellings or unsafe action ordering instead of the
   publicly specified semantics.

The first two failed result sets remain immutable. This protocol does not retroactively replace
their outputs, traces, ratings, or limitations.

## Controlled product change

Eligible evidence is unchanged. The independently constructed strong static profile is unchanged.
The compiled material contains the same active behavioral rules, rendered with stronger obligation
language and an explicit instruction to apply every relevant rule. No behavior is learned from
agent output, tool output, repository content, or scorer output.

## Clean comparison

- Four new, non-held-out tasks cover communication, debugging and verification, environment
  safety, and research integrity.
- Each task receives one compiled-adaptation run and one strong-profile run.
- All eight target runs use fresh ephemeral Codex CLI sessions, saved ChatGPT authentication,
  GPT-5.6 Luna at medium reasoning, identical task delivery, and identical sandbox limits.
- One fresh GPT-5.6 Sol extra-high context judges four anonymous pairs without tools, automated
  scores, condition identities, repository access, prior context, or external-study access.
- The maximum is nine subscription sessions and zero provider-billed calls. There are no retries.

## Semantic oracle contract

Every check has a public basis in the task prompt or module contract. The scorer must accept
semantically equivalent implementations and cannot require undisclosed exact vocabulary.
Generated shell commands are parsed as shell words rather than matched to one command string.
Recovery actions are checked for the safe order: report risk, create backup, verify backup,
replace, and provide a restoration hint.

## Primary gate

The gate passes only when:

1. all eight trial instruments are valid;
2. compiled adaptation passes every objective check;
3. compiled adaptation passes every neutral-control check;
4. for each family, compiled adaptation is no worse than the strong profile on objective,
   diagnostic, neutral, and behavior-conformance measures; and
5. the compiled material is smaller than the strong profile.

The isolated judge is secondary and cannot rescue a failed primary gate. A passing gate permits
only the bounded claim that compiled adaptation matched or outperformed the strong profile across
these four development families while retaining lifecycle and compactness advantages. It does not
establish population-level superiority or cross-agent transfer.

## Boundaries

No API key, provider-billed call, Claude execution, sealed external-validation task, condition
mapping, randomized order, or custody payload may be accessed. Network is available only to the
pinned Codex authentication/model endpoint through the target runner. Raw traces remain encrypted
outside the repository.
