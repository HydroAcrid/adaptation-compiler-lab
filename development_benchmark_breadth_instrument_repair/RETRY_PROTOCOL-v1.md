# Milestone 6A.4 v3 Runner Retry

## Justification

The first clean-grid attempt is an instrument failure. Every target stopped before repository
access because the pinned Codex nested sandbox requires empty `.agents` and `.codex` mountpoints.
Its condition mapping remains sealed, no judge ran, and no task implementation was inspected or
produced. The task payloads therefore remain unseen by the isolated target contexts.

The v3 runner retains the required empty ephemeral mountpoints during execution and removes their
empty host mountpoints before scoring. A real pinned Luna subscription smoke proved source editing,
test execution, registered-path isolation, trace conformance, and control-mount cleanup.

## Retry boundary

- Task payloads, semantic scorers, eligible evidence, compiled material, strong profile, model,
  reasoning, delivery channel, permissions, time limit, and turn limit are unchanged.
- A new private randomization seed creates new blind IDs and order.
- Eight fresh Luna sessions execute the four task pairs once.
- There are no retries within this grid.
- One fresh Sol extra-high context may judge the four anonymous pairs only if all eight target
  instruments are valid.
- The maximum is nine additional subscription sessions and zero provider-billed calls.

## Gate

The primary gate is unchanged: valid instruments, perfect compiled objective and neutral checks,
no compiled family regression against the strong profile, and a smaller compiled material. The
judge remains secondary and cannot rescue the primary gate.

The failed v2 packet remains immutable and is reported alongside the retry. Passing this retry
supports only the bounded development claim from the original clean protocol; it does not erase
the instrument failure, establish population-level superiority, or prove cross-agent transfer.

The deferred external-validation study remains sealed and inaccessible.
