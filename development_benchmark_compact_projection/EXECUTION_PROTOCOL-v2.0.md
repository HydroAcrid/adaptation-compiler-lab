# Typed Decision Projection Execution Protocol v2.0

## Purpose

This public development comparison follows the frozen v1.19 failure. It tests a
general product correction: explicit branch conditions, ordered actions, and
prohibited actions are stored in versioned decision tables bound to exact
governed artifacts. Immutable v1 artifacts and their evidence lineage are not
rewritten.

The deferred Milestone 6 external-validation study remains sealed and is not
accessed, modified, or required.

## Conditions

- `strong_static_profile` uses the already frozen, independently authored and
  independently reviewed v1.14 static profiles.
- `compiled_adaptation` uses the deterministic v2.0 typed-decision projection.
- Both conditions use the same accumulated eligible evidence and the same
  condition-neutral execution envelope.
- Condition identities and run order remain secret until the target records and
  isolated judge receipt are frozen.

## Fresh development tasks

Three new non-held-out publishing-policy tasks use fresh source text and action
vocabulary. There is one task for each evidence stage:

1. addition of the persistent-target safety behavior;
2. a narrower disposable-cache exception;
3. supersession of the persistent-target default while retaining the exception.

Each task has diagnostic, neutral, and objective scorer cases. Visible tests
cover only stable public behavior, so success requires correct use of the
condition material rather than copying a visible expected branch.

## Session budget

The run uses at most eight saved-ChatGPT subscription sessions:

- one live instrument smoke;
- six target sessions, one per condition and task;
- one anonymous, tool-free secondary judge.

No API key, provider-billed call, retry after target action, or additional
profile-authoring session is permitted.

## Isolation

The pinned Codex CLI, model, reasoning level, service mode, target runner, and
outer Bubblewrap policy are identical across conditions. Each target gets a
fresh disposable repository and configuration directory. Only the registered
production source file is host-backed writable. Ephemeral `.agents`, `.codex`,
and temporary paths exist inside the nested sandbox. Network, ambient
instructions, user configuration, memories, skills, plugins, MCP servers,
credentials, other conditions, prior transcripts, and sealed benchmark
materials are unavailable.

The independent scorer runs after Codex exits. Its exact task manifest, source
tree, patch, trace, and command digests are captured. Test and scorer commands
have timeouts and the scorer receives a trusted system path containing standard
administrative binaries needed by the sandbox.

## Primary gate

The typed-decision condition passes only if:

- all six target records are valid;
- every compiled diagnostic and objective case passes at every stage;
- every compiled neutral case passes, giving zero false activation and zero
  scope leakage;
- compiled has no automated regression against the strong profile at any stage;
- compiled target-visible bytes do not exceed the strong profile at any stage;
- provenance and revocation manifests validate;
- condition mapping remained hidden through the judge receipt;
- provider-billed calls and external-validation access remain zero.

The isolated judge is secondary and cannot rescue a failed automated gate.
Failures are frozen unchanged. Any later iteration requires a new
preregistration and fresh tasks; completed outputs are never replaced.
