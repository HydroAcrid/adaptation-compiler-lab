# Complete Decision Table Execution Protocol v2.1

## Purpose

This public development comparison follows the frozen v2.0 failure. It tests
two general instrument and product corrections without rewriting any completed
output:

1. the compiler emits an exhaustive typed table for the registered decision
   dimensions, including positive, negative, and unlisted-case preservation
   branches;
2. the command audit distinguishes the disposable virtual `/workspace` from
   actual host, parent, or internal control-surface access.

Immutable evidence, governed artifacts, the frozen v1.14 strong profile, and all
v2.0 outputs remain unchanged. The deferred Milestone 6 external-validation
study remains sealed and is not accessed, modified, or required.

## Conditions

- `strong_static_profile` uses the frozen, independently authored and reviewed
  v1.14 static profiles.
- `compiled_adaptation` uses the deterministic v2.1 complete typed-decision
  projection.
- Both conditions receive the same eligible evidence and identical
  condition-neutral execution envelope.
- Condition identities and run order stay secret until all target records and
  the isolated judge receipt are frozen.

## Fresh development tasks

Three new non-held-out promotion-policy tasks use a new source vocabulary and
action vocabulary. There is one task for each evidence stage:

1. addition of recovery for an existing persistent target;
2. a narrower atomic-promotion rule for a disposable generated preview;
3. supersession of the persistent default while retaining its explicit
   recovery-request exception and the generated-preview rule.

Each task contains two diagnostic cases plus neutral and objective controls.
Visible tests cover only stable public behavior. The independent scorer invokes
the production function for every frozen scenario after the target exits.

## Session budget

The run uses at most eight saved-ChatGPT subscription sessions:

- one fresh live instrument smoke;
- six target sessions, one per condition and task;
- one anonymous, tool-free secondary judge.

No API key, provider-billed call, post-action retry, profile-authoring session,
or hidden external-validation access is permitted.

## Isolation and command audit

The pinned Codex CLI, `gpt-5.6-luna` model, medium reasoning level, standard
service mode, target runner, and outer Bubblewrap policy are identical across
conditions. Each target receives a fresh disposable repository and
configuration directory. Only the registered source file is host-backed
writable.

`/workspace` is the intended inner-sandbox root and may be inspected.
`/workspace/.agents` and `/workspace/.codex` are private ephemeral control
surfaces and may not be inspected. Host paths, parent traversal, root
enumeration, network commands, credentials, memories, skills, plugins, MCP
servers, prior transcripts, other conditions, and sealed materials remain
unavailable. The command audit records each attempted command and fails the
record on any prohibited access.

## Primary gate

The compiled condition passes only if:

- all six target records are instrument-valid;
- every compiled diagnostic, neutral, and objective case passes;
- compiled has no automated regression against the strong profile;
- compiled target-visible bytes do not exceed the profile at any stage;
- provenance and revocation manifests validate;
- condition mapping remains hidden until the judge receipt is frozen;
- provider-billed calls and external-validation access remain zero.

The judge is secondary and cannot rescue a failed automated gate. Any failure
is frozen unchanged; a later product iteration requires another preregistration
and fresh tasks.
