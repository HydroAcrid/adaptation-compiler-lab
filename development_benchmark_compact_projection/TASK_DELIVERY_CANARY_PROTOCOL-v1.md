# Task-Channel Delivery Canary Protocol v1

## Question

Does delivering the exact task-scoped compiled artifact once in the user-task
channel cause a fresh Codex target to apply the stage-1 rule without inventing
or preserving the wrong recovery-request exception?

This is a one-session product-adapter canary. It does not replace the immutable
twelve-run study or the failed closed-world canary and cannot establish
comparator superiority or cross-agent transfer.

## Evidence-justified change

The closed-world canary received the correct semantic material in the isolated
developer profile, preserved the neutral branch, but still treated the
recovery request as the deciding condition. Its trace showed the task prompt and
repository were treated as the concrete specification while the task-scoped
adaptation remained background policy.

The portable semantic release and closed-world renderer are unchanged. A typed
`TaskMaterialDeliveryReceipt` now binds:

- the original task-prompt digest;
- the exact compiled-material digest and UTF-8 byte count;
- the delivered task-prompt digest;
- the `user_task` channel;
- exactly one material occurrence.

Safety, tool, network, isolation, and research-condition rules remain in the
developer channel. The compiled artifact is placed before the concrete task in
the user request. It is not duplicated in the developer profile. This routing
is target-adapter behavior and can be applied identically to future condition
materials.

## Fresh task and subscription impact

One new non-held-out task uses another unseen action vocabulary and the same
four registered scenario classes. Exactly one additional saved-ChatGPT
subscription target session is permitted. There is no retry, comparator, judge,
API key, provider-billed call, or sealed external-validation access.

## Isolation and pass gate

The canary uses the pinned Codex CLI, `gpt-5.6-luna`, medium reasoning, standard
service, valid v2.1 smoke receipt, independent scorer, hardened command audit,
and outer Bubblewrap sandbox. Only `src/transfer_policy.py` is writable.

The canary passes only if the delivery receipt revalidates, the target record is
valid, the hardened audit reports no violation, every diagnostic, neutral, and
objective scenario passes, the visible suite executes two tests, the workspace
and configuration are destroyed, the compiled material remains no larger than
the frozen stage-1 profile, provider-billed calls remain zero, and sealed
external validation remains untouched.
