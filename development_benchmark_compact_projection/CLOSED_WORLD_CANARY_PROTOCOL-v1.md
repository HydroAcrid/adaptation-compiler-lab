# Closed-World Semantic Canary Protocol v1

## Question

Does the smallest evidence-justified renderer correction prevent a fresh Codex
target from inventing behavior for unnamed cases while applying the stage-1
persistent-content rule?

This is a one-session post-study product canary, not a continuation or
replacement of the immutable twelve-run Milestone 6A.1 study. It cannot support
a comparator-superiority or cross-agent claim.

## Registered correction

The failed semantic remediation result and encrypted trace remain immutable.
The trace showed that the target received the stage-1 material but inferred the
stage-3 persistent exception and stage-2 cache behavior from unused operation
names. It also inspected relative `.agents` and `.codex` paths that were empty
isolated tmpfs mounts; the frozen audit failed to classify that command.

Renderer v3.1 changes expression only:

- the directive says the listed rules are closed-world and forbids inference
  from operation names;
- the persistent rule uses `always` and explicitly covers the absence of a
  recovery request;
- the preservation rule says every other case remains unchanged.

Portable semantic selectors, operations, evidence, consent, lifecycle,
revocation, scope, and provenance are unchanged. The command audit is replaced
with a separately versioned implementation that rejects absolute and relative
control-surface inspection.

## Fresh task and subscription impact

One new non-held-out task uses a previously unseen action vocabulary and the
same four registered scenario classes: two diagnostic persistent cases, one
neutral preview case, and one objective new-target case.

Exactly one additional saved-ChatGPT subscription target session is permitted
under Kevin's post-study instruction to continue genuine product remediation.
It is recorded separately from the closed twelve-run study. There is no retry,
comparator, judge, API key, provider-billed call, or sealed external-validation
access.

## Isolation and pass gate

The canary reuses the pinned Codex CLI, `gpt-5.6-luna`, medium reasoning,
standard service, valid v2.1 smoke receipt, independent scorer, and outer
Bubblewrap sandbox. The task receives a fresh disposable workspace and
configuration. Only `src/transfer_policy.py` is writable.

The canary passes only if the target record is valid, the hardened audit reports
no violation, every diagnostic, neutral, and objective scenario passes, the
visible suite actually executes two tests, the workspace and configuration are
destroyed, the rendered material is no larger than the frozen stage-1 profile,
provider-billed calls remain zero, and sealed external validation remains
untouched.
