## Package qualification

The engine bundles a fixed allowlist of public source snapshots and frozen
calibration inputs. Snapshots of Python files are inert text, not executable
fallback modules. No owner evidence, authentication or qualification certificate
is embedded in the app or committed. Missing compiled inputs fail closed; the
engine cannot fall back to a development checkout. The build compares compiled
`--calibration-info` against source inputs in an empty process profile.

`--qualify-calibration` accepts only bounded detection/native run names under the
configured protected state directory. It validates their signed chains, exact
source/model/runtime bindings and encrypted observations before issuing a
dedicated owner-signed certificate and recording calibration. It does not enable
personalization, change a grant or publish instructions. The renderer has no
general evidence/calibration injection operation.

The retained certificate records validation facts and source heads. Its signature
purpose differs from ordinary event signatures. Readiness checks bind it to the
owner, current public inputs, release and model/runtime. Raw responses still expire
after thirty days; that deletion does not erase the signed validation facts or
require indefinite retention of conversations. Interrupted installation can resume
from a current valid certificate. A privileged local holder of the owner's signing
key can fabricate local attestations, as with the existing owner event ledger.
The existing five-minute app maintenance tick sweeps the bounded validation-run
stores as well as personal evidence, including when learning is paused. Native
records use their verified signature times; interrupted orphan writes use file
age. An app that is closed performs overdue cleanup when maintenance next runs.
