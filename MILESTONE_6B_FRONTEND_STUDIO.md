# Milestone 6B: Frontend Studio Mode

Status: implemented as the first bounded temporary capability; product-efficacy testing remains distinct from conformance.

## What it is

Frontend Studio is a versioned first-party Mode that adds a compact frontend workflow for one exact managed task. It is not copied into the user's permanent Core. Its defaults cover visual direction, design-system continuity, responsive behavior, accessibility, complete product states, and honest rendered/test validation.

The target projection is deliberately small and contains no source prose, audit metadata, tool recommendations, evidence, private paths, or executable content. It declares compatibility with Codex and Claude Code, while the first live delivery path is the existing isolated Codex task gateway.

## Authority and scope

Mode guidance is lower authority than:

1. the user's current request;
2. repository policy and security constraints;
3. applicable permanent personal requirements; and
4. a future personal overlay for the Mode.

An activation is signed and bound to the exact subject, project, target family, task digest, Mode version/digest, and prior Core release digest. The default lease ends with that task and also expires after four hours. A higher-authority conflict suppresses only the matching Mode claim. Unknown suppression keys fail closed.

The managed task path records a signed raw-free activation and delivery before target execution. It records a signed deactivation on completion or failure and requires the restored Core digest to equal the pre-Mode digest. Task text and repository content do not enter the Mode receipt ledger.

## Deterministic evaluation

`evaluate_frontend_studio_mode()` performs a zero-provider-cost conformance matrix. It verifies:

- compact projection size;
- presence of the intended frontend workflow dimensions;
- no requested tools or integrations;
- one-task, non-permanent lifecycle;
- explicit target compatibility; and
- exclusion of unrelated backend and research task classes.

Unit coverage additionally proves exact task/project/target/expiry matching, claim-specific suppression, append-only raw-free receipts, and exact clean deactivation.

This establishes that the Mode machinery composes and removes Frontend Studio safely. It does **not** establish that an agent produces better frontend work. That claim requires fresh relevant tasks, neutral controls, automated correctness/accessibility checks, and blinded quality comparison after the product channel is stable.

## Boundaries

- No model call occurs during Mode selection or composition.
- No tool is installed or authorized by the Mode.
- No external Mode marketplace or remote import exists.
- No Mode becomes permanent learning automatically.
- The sealed Milestone 6 external-validation study is not accessed or modified.
