# Persona v3 Construction Smoke — Failure Analysis

## Outcome

The construction smoke is valid as a recorded instrument run and failed its preregistered pass
rule. It used three successful isolated Codex sessions, one failed pre-output transport launch, and
zero provider-billed calls. The deferred Milestone 6 study was not accessed.

| Lane | Durable claims retained | Exact state | Principal discrepancy |
| --- | ---: | --- | --- |
| Compiled | 0 | No | Turns 2 and 6 were proposed as examples and failed deterministic review. |
| Strong static profile | 2 | No | Both were routed as procedures; turn 2 was expected as a preference. |

## What the run measured

The static lane successfully separated durable feedback from all five ordinary or task-only
messages, kept the narrow incident behavior separate, cited the exact two source turns, and received
the correct host-owned scopes. Its only mismatch was route classification for turn 2.

The compiled semantic sensor correctly marked the five ordinary or task-only messages as
non-promotable. For both durable messages it set `example_intent=endorsed_for_reuse`, even though no
concrete example was presented or endorsed. It also returned `permanent_profile` despite the named
River Station boundary. Turn 6 was marked as a correction, which is defensible because the fixture
called it a “narrow exception,” but the smoke review only authorized additions. Deterministic review
therefore rejected both durable proposals and correctly failed closed.

## Root-cause classification

1. **Instrument ambiguity:** “outcome first, then evidence” is both a soft choice and an ordered
   presentation sequence. Under Temper's current route policy, a repeatable sequence routes to a
   procedure. The strong profile's answer was therefore reasonable and the preference-only oracle
   was too narrow.
2. **Instrument ambiguity:** “that's the narrow exception” suggests correction of prior behavior,
   while the oracle modeled a separate addition. The fixture did not isolate those lifecycle forms.
3. **Semantic-sensor defect:** future applicability was confused with positive-example intent.
   Endorsed examples require a concrete demonstrated artifact or output plus an instruction to
   imitate it; neither message contained one.
4. **Semantic-sensor defect:** a clearly named project was classified as permanent-profile scope.
   Host scope prevented leakage, but the semantic feature was still wrong.
5. **Transport defect, repaired:** the initial profile output schema was not fully required under
   Codex strict structured output. Amendment 1.1 fixed only schema transport and preserved the failed
   launch.

## Consequence

No pass is claimed, no prompt or pack is tuned against the frozen Sable answer, and the full v3 grid
is not authorized. A replacement instrument smoke must use a fresh persona and genuinely new text
that cleanly separates a non-sequential soft preference from a triggered procedure. The shared
semantic contract may clarify that future applicability establishes durability, not example intent.
That general clarification must be frozen before the replacement evidence is generated or run.
