# Milestone 6A.4 Oracle-Contract Remediation Protocol

## Why this repair exists

The original eight-task breadth run is immutable. Its v1 scorer adapter failed, and the valid v1.1
adjudication then showed that five task pairs depended on exact hidden vocabulary or return tokens
not defined by their public contracts. Examples included requiring one valid copy flag over
another, a specific source label, and precise action-token names. Those five pairs cannot support
the product gate.

Three original pairs remain valid and perfect for both conditions:

- `communication-handoff`;
- `debugging-request-context`;
- `research-advisory`.

This remediation preserves those pairs and substitutes five entirely fresh tasks for the invalid
slots. It does not rewrite, rescore, or rerun an original target.

## Oracle-contract audit

Every replacement manifest registers each objective, diagnostic, and neutral check with:

- a stable check ID;
- its score group;
- the public prompt, module contract, or approved evidence that supports it;
- an assertion that no undisclosed exact vocabulary is required.

The scorer's observed check IDs must exactly equal the manifest's registered IDs. Starter fixtures
must pass two visible tests while remaining diagnostically incomplete. References must pass every
registered check. This audit is frozen before target execution.

## Fresh replacement tasks

The five non-held-out replacements are:

- communication: macOS zsh archive-copy handoff with arbitrary literal paths;
- debugging and verification: live deployment-ledger status under published value constants;
- environment safety: publish actions under published stable action constants;
- environment safety: synchronization layout and recovery actions under published constants;
- research integrity: frozen-protocol reporting under published fields and classifications.

They replace only the five failed v1.1 slots. Combined with the three inherited pairs, the final
matrix again contains two tasks per approved source family. Conditions use the unchanged compiled
and strong-profile materials frozen in the original breadth design.

## Execution and blinding

A new owner-only 32-byte seed outside Git determines task and within-pair condition order. The
public plan exposes only its commitment, anonymous condition IDs, and all 10 cells.

Every target uses pinned Codex CLI 0.145.0, `gpt-5.6-luna`, medium reasoning, Standard service,
saved ChatGPT authentication, and a 600-second ceiling. API keys, provider-billed calls, retries,
network, ambient instructions, host files, prior sessions, comparator output, and deferred
external-validation custody are forbidden.

Both conditions use the same exact-once `user_task` delivery adapter. Each target receives a fresh
disposable Git workspace and configuration. The direct scorer runs in a no-network read-only
bubblewrap boundary and its three boolean maps are counted directly—never through the legacy
`checks`/`receipts` adapter.

## Scoring and gate

Automated objective, diagnostic, and neutral checks are primary. False checks are retained by
group and name as behavior failures. Instrument failures remain separate from task failures.

After 10 integrity-valid receipts are sealed, one fresh tool-free `gpt-5.6-sol`/`xhigh` context
judges the five anonymous pairs. It cannot see condition materials, mappings, automated scores,
prior results, repository state, or external custody. Its decision is secondary.

The combined gate passes only when:

- all 10 new receipts have complete integrity and exact-once task delivery;
- every new compiled run passes every registered check and is behavior conformant;
- all three inherited compiled runs used in the combined matrix already passed every check;
- compiled has no regression against the profile within any source family;
- all four combined family gates pass;
- compiled remains strictly smaller than the profile at every evidence stage;
- provider-billed calls, API-key use, external-validation access, and condition changes remain
  zero.

If compiled scores higher, the bounded claim is
`compiled_outperformed_on_combined_multifamily_suite`. If it ties, the claim is
`compiled_matched_profile_across_all_approved_families_with_lifecycle_advantages`. Otherwise the
result is `breadth_remediation_gate_failed`.

## Subscription impact

This repair permits 10 Luna/medium targets and one Sol/xhigh blind judge: 11 subscription sessions
maximum and zero provider-billed calls. No retry or additional profile-construction session is
authorized.
