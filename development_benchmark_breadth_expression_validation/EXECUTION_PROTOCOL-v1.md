# Milestone 6A.4 Scoped Expression-Validation Protocol

## Purpose

This zero-provider-billed gate tests the smallest justified repair after the valid v3
breadth comparison: strengthen only the compiled communication rule so that matching a
named environment means using real supported commands and options and avoiding unsupported
verification claims.

No new user behavior or evidence is introduced. The strong static profile is unchanged.
All non-communication compiled rules are byte-identical to the prior valid comparison.

## Fresh tasks and comparison

- One communication task directly exercises the repaired expression.
- One unrelated research-integrity task detects scope leakage or regression.
- Both compiled adaptation and strong static profile receive the same task through the same
  user-task delivery adapter.
- Each condition runs once on each task in a fresh isolated Codex session: four target
  sessions total.
- One fresh isolated Codex judge compares anonymous outputs after the instrument-valid
  blind packet is sealed. Automated scoring remains primary.

The communication task publicly requires macOS zsh, the POSIX `cp` utility, macOS-supported
options, literal-path handling, purpose-first communication, and honest non-execution.
The semantic scorer does not require undisclosed wording or a hidden implementation.

## Inherited evidence

The prior v3 result is immutable and digest-bound. Its valid debugging, environment-safety,
and research-integrity pairs remain part of the bounded four-family claim only when:

1. all three automated outcomes remain ties;
2. this repair changes only the communication rule; and
3. the fresh unrelated control shows no compiled regression.

The prior failed communication pair is not replaced or rewritten. The fresh communication
pair is an explicitly versioned expression-validation result.

## Execution and isolation

- Target: pinned `codex-cli 0.145.0`, `gpt-5.6-luna`, medium reasoning.
- Judge: pinned `gpt-5.6-sol`, extra-high reasoning, no tools.
- Authentication: saved ChatGPT authentication only.
- `CODEX_API_KEY` and `OPENAI_API_KEY` are forbidden.
- Provider-billed calls: zero.
- Target runner: smoke-validated v3 nested sandbox.
- Network, agents, MCP, skills, plugins, memories, ambient instructions, prior transcripts,
  comparator outputs, external files, and the sealed external-validation study are unavailable.
- Only the registered task source is writable. Tests and scoring run independently with
  bounded commands and timeouts.
- Raw traces remain encrypted outside the repository.
- There are no retries inside this frozen grid.

## Primary exit gate

The scoped repair succeeds only when:

1. all four trial records are instrument-valid;
2. compiled adaptation passes every objective, diagnostic, neutral, and bounded-command check;
3. compiled adaptation is no worse than the profile on every fresh task score dimension and
   behavior-conformance flag;
4. the three prior non-communication pairs remain digest-bound automated ties;
5. the non-communication compiled material is byte-identical;
6. the repaired compiled pack remains smaller than the strong profile.

The blind judge is secondary evidence and cannot rescue a failed primary gate.

On success, the permitted bounded claim is that compiled adaptation matched or outperformed
the strong profile across the four approved behavior families in this Codex-subscription
development evidence while retaining lifecycle advantages. This is not cross-agent validation,
general superiority, or external validation.

## Budget and custody

Maximum new subscription sessions: five (four Luna target sessions and one Sol judge
session). No provider-billed calls are allowed. The deferred Milestone 6 Claude registration,
sealed bundle, tasks, condition mapping, order, authorization gate, and custody records remain
untouched and unaccessed.
