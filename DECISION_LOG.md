# Decision Log

Last updated: 2026-07-22

This log separates choices implemented through Milestone 2 from choices gated to later milestones.
No entry authorizes a fixed project exclusion or permits starting the next milestone without
explicit approval.

| D-023 | Withdrawal and recall | **Implemented 2026-07-22; owner: prototype architecture.** Signed impact/invalidation/tombstone/report objects drive consent revocation, Evidence restriction/purge, Artifact revocation, Release retirement, TargetPack invalidation, and atomic affected-pointer deactivation. | D-027 | Evidence schema evolution | **Implemented.** Keep all v1.0 schema snapshots immutable and canonical digests compatible. Define v1.1 only for Evidence, requiring exact consent/capture references for non-synthetic sources. No automatic migration rewrites v1.0 records. |
| D-028 | Milestone 1 CLI/data boundary | **Implemented.** Add identity, consent, and capture-preview commands but accept synthetic selectors only. Real source enumeration, capture, consent selection, and agent calls remain unreachable. |
| D-029 | Recall confirmation binding | **Implemented 2026-07-22; owner: prototype architecture.** Persist a signed `DependencyImpact`, expose its full canonical digest as the only confirmation token, recompute under the execution transaction, and require a new preflight after any graph/head change. |
| D-030 | Recall cascade and atomicity | **Implemented 2026-07-22; owner: prototype architecture.** Traverse exact incoming provenance links plus consent/capture and active-pointer edges. | D-031 | Purge transaction boundary | **Implemented provisionally 2026-07-22; owner: prototype architecture.** Authenticate/read selected ciphertext, append signed tombstones and recall metadata, unlink before SQLite commit, and restore the same content address if commit fails. | D-032 | Revoked-material availability | **Implemented 2026-07-22; owner: prototype architecture.** Treat lifecycle overlays as authoritative availability state. Lesson/artifact approval, release freeze, pack compilation, and activation fail closed on restricted, purged, excluded, revoked, retired, invalidated, or expired dependencies. |
| D-033 | Signer-key revocation and rotation | **Open; initial recommendation.** Add a separately signed identity-status event and replacement-key chain before any real-data operation; do not reuse content recall to invalidate signing authority, and require an offline recovery procedure. |
| D-034 | Operational deletion assurance | **Open; initial recommendation.** Before real data, document workspace backup/snapshot exclusions, retention enforcement, SSD/cloud-sync limitations, and an auditable purge verification procedure; do not claim cryptographic erasure from file unlink alone. |
| D-035 | Semantic conflict discovery | **Open; initial recommendation.** Keep conflict declaration human-reviewed and claim-specific. Deterministic code may propose candidates from explicit corrections, but no model or untrusted content may silently declare or arbitrate a conflict. |
| D-036 | Multi-process/device recall coordination | **Open; initial recommendation.** Retain single-host SQLite `BEGIN IMMEDIATE` and head checks for the feasibility pilot. If multi-device operation is later authorized, introduce a transactional coordinator rather than weakening stale-impact rejection. |

## Decision process

When an open item is decided, add the date, owner, selected option, affected documents, and any
migration/test impact. Do not delete the prior recommendation. Changes motivated by seen held-out
results are post hoc and cannot replace the preregistered decision for that experiment.
