# Discovery and maintenance development screen

This new experiment tests a bounded convenience hypothesis. The earlier rapid,
real-repository repair, setup/recovery, and habit-learning studies are unchanged.
No GitHub CI, product installation, personal grant change, or model substitution
is part of this experiment.

## Implemented prototype

`scripts/discovery_maintenance.py` provides public GitHub revision acquisition,
bounded archive intake and cache integrity, discovery from authorized skill roots,
metadata ranking against a natural work goal with a repository-context tie-breaker,
and a separate maintained profile per project. It copies full resource trees,
keeps untracked owner material, defers declared incompatible updates, pauses on
externally edited managed files, and converges after interrupted file publication.
It can remove its own tracked files while preserving unrelated files.

This is sandbox-only prototype code. It does not change the installed Temper app
or Foundry quarantine, provision arbitrary framework runtimes, continuously run a
background discovery service, infer personal preferences, establish a new source's
trust, or solve arbitrary semantic native-policy conflicts. A caller supplies each
goal and invokes maintenance. In the comparison that caller is the same configured
native Codex model in every arm. No extra selector/model calls are hidden.

Before freezing the comparison, a reference flow caught the prototype selecting
TypeScript coding guidance for documentation work. The corrected ranker requires
a task-term match independent of words already found in the project manifest;
stack overlap alone cannot activate a skill. A regression test covers this case.
This is development feedback, not held-out efficacy evidence.

## Three conditions

1. Native agent using Skills CLI 1.7.2 and ordinary Git/filesystem helpers.
2. Native agent using SkillKit 1.24.0, including discovery/recommendation and native
   installation/maintenance. Ordinary backups/recovery helpers remain allowed.
3. Native agent using the experimental Temper discovery/maintenance CLI.

All use the saved ChatGPT authentication, configured verified model and effort,
same tool/time budget, actual real-repository fixtures, isolated private HOME,
same source snapshots, and identical task/event sequence. Default SkillKit
optional dependencies were installed, rather than omitting its large optional
native libraries. Additional provider/model calls and downloaded embedding-model
inference are excluded in every arm; the native operator supplies semantic judgment.

The sources are a finite registry of complete main `skills/` roots from the pinned
pstack, Ponytail, and Superpowers repositories. Goals do not prescribe skill names.
Every arm can inspect all metadata, source instructions and resources. Source
acquisition and trust/bootstrap effort are disclosed, not treated as nonexistent.
The SkillKit cache is populated by its exported native discovery/parser/index
APIs with this same corpus, no relevance labels, and its native neutral defaults.
This tests offline registry replay, not its default online source-index build.

## Actual workflow and acceptance

Use the full historical Temper/Python and Kairn/TypeScript repositories from the
previous real-repository study, including existing Git data and native policy.

The host checks eight sequential phases:

1. Equip Python for intermittent failures, root-cause diagnosis and regression tests.
2. Switch to TypeScript documentation work, without activating coding guidance.
3. Return to the prior Python goal and preserve its useful profile.
4. Apply a compatible source/resource update.
5. Keep the working profile when the available release requires Node 99.
6. Repair a deleted resource while preserving concurrent owner notes/policy edits.
7. Disable irrelevant specialization for a plain Git-branch inspection task.
8. Remove managed profiles and registrations from both projects, preserving owners.

The v2/v3 releases are controlled edits of public snapshots, not assertions about
real upstream releases. The partial-copy event is file deletion, not a killed
upstream installer. Actual process-interruption recovery is exercised separately
by prototype tests. Real public-head refresh/cache reuse is a separate live probe.

Acceptance uses frozen broad applicability sets, complete source bodies/resources,
app-source preservation, owner guidance/configuration/notes, snapshot integrity,
safe updates, and real Codex `skills/list` metadata discovery. Installation and
metadata discovery do not prove an existing chat loaded or followed instructions.
This is workflow setup/maintenance; no coding-quality improvement is inferred.

Host checkpoints expose missing constraints, never solutions or ideal source IDs.
All retries count. `hub_escalate` records required owner intervention; approval is
never simulated. Owner attention itself is unmeasured because this is an automated
operator experiment. Zero escalation is not proof of zero real-world human effort.

## Measurement

Six fresh native turns: two complete journeys per condition, in forward then
reverse condition order. No primary result is discarded, tuned against, or rerun.
This small development screen cannot establish general superiority or equivalence.

Record full workspace extraction and Git setup, native index preparation,
authentication/model/capacity admission, all operator tools and retries, checks,
profile changes, source switches, native metadata readers, encrypted evidence
persistence, and separately measured safe cleanup. Count cached/uncached input,
output and reasoning (reasoning is a subset of output). Report setup and operating
time separately and combined. Include failed preparation attempts and live probes.
Helper/checkpoint timing is nested within whole timings; do not sum it twice.

Observed footprint includes sources, copies, backups and manager state in writable
workspaces after tool calls, a lower bound on transient peak storage. Full manager
dependency caches and retained public source caches are separately reported.
Prototype/instrument development wall time is experiment overhead, not a future
product's onboarding time. Active coordinator time/tokens, human research time,
provider HTTP requests and billed cost are unknown rather than zero.

## Execution and replay

The new `protocol.json` binds all code/inputs, source tree hashes, native package
locks and configured model/effort before primary execution. Keep raw model text,
events and private receipts outside Git and Obsidian, with model evidence encrypted.

```text
.venv\Scripts\python.exe -m scripts.prepare_discovery_maintenance
.venv\Scripts\python.exe -m scripts.probe_discovery_maintenance --output <new-private-controls> --native
.venv\Scripts\python.exe -m scripts.run_discovery_maintenance_screen --output <new-private-run>
```

This instrument requires the previously declared Windows/WSL/Python/Node/Codex
runtimes and public snapshot cache; it is not a clean-machine product installer.
Native source trees are verified against the previous snapshot bindings. Exact
package locks preserve native dependency resolution independently of GitHub HEAD.
No push, PR, CI, package release or market claim is implied.
